# GitHub PR과 Vercel 배포 절차

## 적용 범위

랜딩 페이지 코드 변경을 GitHub에 올리고 Vercel에서 검증·배포할 때 사용한다.

## 순서

1. `git status --short`로 사용자 변경과 미추적 파일을 확인한다.
2. 필요하면 `codex/<작업명>` 브랜치를 만든다.
3. 요청한 변경만 구현한다.
4. `npm run build`를 실행한다.
5. 화면 변경이면 주요 언어와 모바일·데스크톱 화면을 확인한다.
6. 관련 파일만 스테이징하고 Conventional Commits 형식으로 커밋한다.
7. 브랜치를 푸시하고 한국어 PR 제목·본문을 작성한다.
8. Vercel 미리보기에서 페이지 로드, 콘솔 오류, CTA 링크, 이미지 품질을 확인한다.
9. 사용자가 프로덕션 배포까지 요청한 경우에만 프로덕션 배포 또는 승격을 진행한다.
10. 최종 URL과 검증 결과를 보고한다.

## PR 본문 최소 구성

```md
## 목적

## 주요 변경

## 검증

## 배포 영향
```

## 주의사항

- `.vercel/`의 로컬 연결 정보를 커밋하지 않는다.
- 기존 사용자 변경을 되돌리거나 무관한 파일을 포함하지 않는다.
- 배포 성공은 URL 응답과 실제 화면을 확인한 뒤 판단한다.
