# Deep Plate 결정 기록

새로운 중요한 결정을 내릴 때 아래 형식으로 짧게 추가한다. 과거 사실을 추측해 기록하지 않는다.

## D-001: 랜딩 페이지 기술 구성

- 상태: 적용 중
- 결정: React와 Vite 기반의 단일 페이지 애플리케이션을 사용한다.
- 이유: 현재 코드 구조와 배포 파이프라인이 단순하며, 다국어 UI와 반응형 화면을 관리하기에 충분하다.
- 영향: 서버 기능이 필요해지기 전까지 별도 백엔드 프레임워크를 추가하지 않는다.

## D-002: 배포 방식

- 상태: 적용 중
- 결정: GitHub PR로 변경을 검토하고 Vercel로 배포한다.
- 이유: 변경 이력을 남기고 미리보기에서 화면을 확인한 뒤 프로덕션에 반영할 수 있다.
- 영향: 코드 변경은 PR 설명과 빌드 검증 결과를 남긴다.

## D-003: 설문과 운영 데이터 분리

- 상태: 적용 중
- 결정: 고객 입력은 Tally, 원본 응답은 Google Sheets `시트1`, 실무 관리는 `운영 관리` 탭에서 처리한다.
- 이유: 설문 원본을 보존하면서 접수·결제·큐레이션·전달 상태를 보기 쉽게 관리하기 위해서다.
- 영향: 원본 탭을 직접 재구성하지 않고 운영 탭에서 필요한 정보를 참조한다.

## D-004: 다국어 제공

- 상태: 적용 중
- 결정: 한국어, 일본어, 영어를 지원한다.
- 이유: 서울을 방문하는 국내외 여행자를 대상으로 동일한 서비스 흐름을 제공하기 위해서다.
- 영향: 문구와 설문을 변경할 때 세 언어의 노출, 빈 화면, 줄바꿈을 모두 확인한다.
