# Deep Plate React 아키텍처

## 목표

Deep Plate의 코드는 파일 수를 늘리기보다 각 변경의 소유 위치와 의존 방향을 분명하게 유지한다. 화면 디자인, Tally 연결과 다국어 동작을 보존하면서 작은 단위로 검증한다.

## 모듈 책임

```text
main.tsx
  └─ App.tsx
      ├─ components/          재사용 가능한 화면 요소
      ├─ components/sections/ 랜딩 페이지의 독립 섹션
      ├─ hooks/               상태와 브라우저 생명주기를 포함한 행동
      └─ data/                다국어 문구와 정적 서비스 설정
```

- `App.tsx`: 페이지를 조립하고 현재 언어와 설문 열림 상태를 소유한다.
- `components/`: Header, Hero, 설문 모달처럼 독립적인 UI 계약을 가진 요소를 둔다.
- `components/sections/`: 소개, 큐레이션, 이용 방법, FAQ처럼 페이지에서 이름 붙일 수 있는 영역을 둔다.
- `hooks/`: 언어 저장, 캐러셀 타이머, 스크롤 노출처럼 React 외부 시스템과 동기화하는 행동을 둔다.
- `data/`: 세 언어가 같은 키 구조를 유지해야 하는 문구와 Tally 주소를 둔다.

의존은 `앱 조립 → 컴포넌트·섹션 → 훅·데이터` 방향을 유지한다. 내부 파일은 실제 소유 파일을 직접 import하며, 단순한 재수출용 `index.ts`는 만들지 않는다.

## 타입 경계

- 지원 언어, 다국어 문구와 UI 라벨의 공통 계약은 `data/content.tsx`가 소유한다.
- 한 컴포넌트에서만 사용하는 props 타입은 해당 컴포넌트 파일 가까이에 둔다.
- 타입만 모으는 전역 폴더를 만들지 않고, 실제 데이터와 행동을 소유한 가장 좁은 모듈에 둔다.
- `strict`와 `noUncheckedIndexedAccess`를 유지해 누락된 언어, 배열 접근과 DOM 경계를 빌드 전에 확인한다.

## 상태와 Effect

- 현재 언어와 설문 열림 상태는 이를 함께 사용하는 가장 가까운 부모인 `App`이 소유한다.
- 모바일 메뉴와 FAQ 열림 상태는 해당 컴포넌트 안에 둔다.
- `useEffect`는 로컬 저장소·문서 언어, 타이머, IntersectionObserver, 키보드 이벤트와 스크롤 잠금처럼 외부 시스템 동기화에만 사용한다.
- props나 기존 상태로 계산 가능한 값은 별도 상태로 만들지 않는다.

## 테스트 경계

- `App.test.tsx`: 언어 전환과 설문 모달 같은 핵심 고객 흐름을 검증한다.
- `data/content.test.tsx`: 한국어·일본어·영어가 동일한 데이터 계약을 유지하는지 검증한다.
- 내부 구현보다 사용자가 보는 문구, 역할과 동작을 우선해 테스트한다.

## 변경 원칙

1. 새 파일은 독립적으로 설명할 수 있는 책임이 있을 때만 만든다.
2. 컴포넌트 줄 수만으로 분리하지 않는다.
3. 구조 변경과 큰 디자인 변경은 같은 PR에 섞지 않는다.
4. 다국어 키, CTA 동작, Tally 주소와 공개 URL은 리팩터링 중에도 보존한다.
5. 변경 후 `npm run lint`, `npm run test`, `npm run build`를 통과시킨다.

`styles.css`는 현재 가장 큰 결합 지점이다. 별도 리팩터링에서 디자인 토큰·기반 스타일·화면 영역·설문 모달 경계를 기준으로 단계적으로 나누고, 각 단계에서 기존 화면을 비교한다.
